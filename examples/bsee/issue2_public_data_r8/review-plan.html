Revision 8 build and verification plan

Scope: newsletter issue 2, public-data page. Complexity: T2. Execution: one write lane with an independent read-only duration-method review. The originating task will authorize a local commit only. A separate reviewer will control any later publication decision. No matching GitHub implementation issue has been established; the editorial issue number will not be presented as a GitHub ID.

Resource intelligence

  • The supplied r7 HTML, its rig/depth CSVs and counting script will establish the retained content and count basis.
  • The BSEE raw-data index will establish public download URLs. Real archive headers will establish the duration fields.
  • The prior interventions-by-depth branch will supply classification and positive-estimate counting ideas through read-only git show inspection.
  • The catalog identity bsee-data-center will remain the source identity. This example will own the r8 derivatives.

Artifact map and method

  • Tests will precede implementation and cover depth edges, finite positive days, linear quartiles, code precedence, duplicates, fixed pie years and numeric formatting.
  • One build script will verify retained inputs, verify or download receipted sources, print headers, classify records, write CSVs, plot nine figures and render the HTML template.
  • The script will count one APM identifier per submission and one original borehole identifier per recorded interval. Analytical-field conflicts will stop the build.
  • All source classifications, period selections and exclusions will remain visible. Estimate and actual-date bases will remain distinct.
  • The r7 chart counts, Table 1 and specified closing prose will remain unchanged. Figure pies will use 2005, 2015 and 2025.
  • Raw zips will remain in an ignored cache. The page, CSVs, figures, source receipts, input digests, script, tests and documentation will be committed locally by explicit path.

Adversarial plan corrections

  • The method will avoid an unsupported approved-only claim because APM has no separate approval-status field.
  • Completion will not be labelled universally initial completion. Mixed abandonment subtypes will use permanent precedence and retain whole-submission estimates.
  • APM duplicate comparison will include days and depth. Unknown/administrative scope will be excluded rather than counted as physical intervention.
  • Actual date intervals will be labelled calendar intervals, conditional on recorded total-depth dates. They will not be equated with active drilling time.

Acceptance and risks

  • Offline tests will pass. Two complete builds against identical cache receipts will produce identical SHA-256 hashes for every HTML, CSV, PNG and SVG output.
  • The retained CSV totals and pie cells will reconcile exactly. Protected r7 paragraphs and Table 1 will be compared to their source.
  • Headless rendering will check chart initialization and page overflow. Static figure images will receive visual inspection.
  • A frozen code/data/template packet will receive defect-hunting review. Any subsequent change will invalidate the affected verdict.
  • The r7 archive itself is not supplied. Its receipt will be marked inherited; the supplied counts will be preserved.
  • Changing source snapshots, software versions or fonts can change outputs. Historical cache retention will be required to reproduce issued duration values.
