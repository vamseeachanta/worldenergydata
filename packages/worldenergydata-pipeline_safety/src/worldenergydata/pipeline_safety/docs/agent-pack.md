## 1. Purpose and scope

The module normalizes PHMSA Excel incident records into `PipelineIncident`, while a separate workflow characterizes incident dictionaries, calculates FFS pressures and produces verdict reports. [packages/worldenergydata-pipeline_safety/src/worldenergydata/pipeline_safety/importers/phmsa_importer.py:L259-L351] [packages/worldenergydata-pipeline_safety/src/worldenergydata/pipeline_safety/workflow.py:L145-L259]

The importer manifest contains ten workbooks across gas distribution, gas transmission, hazardous liquid and LNG categories; era selection chooses modern, transitional or legacy normalization. [packages/worldenergydata-pipeline_safety/src/worldenergydata/pipeline_safety/importers/phmsa_importer.py:L17-L38] [packages/worldenergydata-pipeline_safety/src/worldenergydata/pipeline_safety/importers/phmsa_importer.py:L353-L375]

The engine route accepts `analysis.type=ffs` and CSV input, then writes a report, summary and narrative; it does not use the database importer to supply measured defect geometry. [packages/worldenergydata-pipeline_safety/src/worldenergydata/pipeline_safety/pipeline_safety.py:L19-L69]

`module-manifest.yaml` labels the module `stable`, but this is a manifest claim rather than demonstrated standards validation or verified dataset completeness. [module-manifest.yaml:L172-L190] [data/catalog/source-registry.yml:L191-L194]

The example contains synthetic incident dictionaries and delegates its calculation to the same workflow, so it is a demonstration rather than an independent benchmark. [packages/worldenergydata-pipeline_safety/src/worldenergydata/pipeline_safety/examples/phmsa_ffs_case_study.py:L1-L9] [packages/worldenergydata-pipeline_safety/src/worldenergydata/pipeline_safety/examples/phmsa_ffs_case_study.py:L292-L312]
