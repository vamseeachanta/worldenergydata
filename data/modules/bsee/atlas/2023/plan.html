2023 BSEE Atlas ingest

The ingest will implement issue 955 within the research and data-curation direction dated 2026-10-11.

A sequential fetcher will discover the download link from the source page, retain the ZIP and Access database outside Git, export the three requested tables through MDB Tools, and emit provenance for every downloaded file and exported table: source URL, retrieval UTC, source-stated terms, SHA-256 and byte size. HTTP refusal will stop downloading, record the refusal and leave actual attribution unavailable; a small handmade fixture will use documented table names only, with no invented source schema; transient errors will receive at most one retry.

The schema will preserve actual exported column names, Access types, nullable cells and identifier strings. Small recorded CSV fixtures will precede the loader and join implementation. Three offline tests will cover malformed data, known attribution, and unmatched/multiple-play outcomes.

The join will associate BOEM_FIELD with canonical registry area blocks, using roster blocks only when canonical identity is unavailable. Because the sands table has no lease column, no lease linkage will be inferred. All area-block-only matches will be classified ambiguous, with candidate plays rather than verified named-field attribution; shared-block roster collisions will be flagged separately and tested; multiple plays and missing lookup rows will remain explicit. Sand identifiers and source row numbers will support readback.

A separate derived JSON table will cover every Gulf of Mexico null-play roster entry and expose canonical IDs when available. Dictionary, manifest, input digests and a dataset freshness record will accompany it. Roster backfill, funnel regeneration and catalog-tail attribution will remain follow-on work.

Formatting, lint, type checks and frozen-packet adversarial review will precede a draft PR. Dependency manifests will remain outside the diff. Only job-owned branch commits will be pushed; issue state will remain open.
