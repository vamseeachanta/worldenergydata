US Gulf of Mexico jack-up and liftboat activity, 1997 to 2025

Summary

A BSEE-only, exact-name-matched subset contains 38,492 WAR reporting records from 370,156 source reports. Each row represents one report, not one well, vessel visit or completed operation. The subset contains 24,610 jack-up and 13,882 liftboat reports; 139 reports exceed the 500 ft screening threshold in at least one supplied depth and remain flagged.

Download and scope

Download the UTF-8 CSV (gzip). The table has 20 columns. The manifest binds the compressed and uncompressed bytes and all retained source archives by SHA-256.

The stable URL pattern after merge is https://raw.githubusercontent.com/<repository-owner>/worldenergydata/main/data/modules/bsee/jackup_liftboat_activity/activity_1997_2025.csv.gz. The default-branch URL will change on refresh; use a commit SHA in place of main for an immutable citation.

Selection uses WAR_START_DT from 1997-01-01 through 2025-12-31, Borehole REGION_CODE=G, and APM rig view RIG_TYPE_CODE in JU/LB. Rig names are matched only after edge trimming and case folding; the published WAR names are preserved. Unmatched and ambiguous names are excluded and counted, without guessing a rig class. No fuzzy matching, contractor-page data or contact fields are used. The full Gulf activity population is not established by this subset.

Screening and known limits

The threshold is strictly greater than 500 ft, from BSEE-USCG, Offshore Oil and Gas Infrastructure for the GOM, Technical Document 1, 1 July 2022, Figure 4 (printed page 6), which gives jack-up water depths up to 500 ft. This published upper range is used for plausibility screening, not as a record of the world's deepest achieved operation or a vessel-specific operating limit. The same permissive threshold screens liftboats; a false flag does not establish vessel capability.

Depths are not corrected or substituted. A disagreement between WAR and borehole values is flagged. A borehole depth may describe a subsea well rather than the rig's physical location; no elevation, leg length or geotechnical basis is supplied. Blank/negative/non-numeric depths are retained and marked. Generic rig labels beginning with an asterisk are retained and flagged.

The nine 8,831 ft source WAR records identify CR LUIGS and have no exact name match in the coded rig view. Their identifiers and exclusion reasons are preserved in source_8831_ft_record_audit in the manifest. BSEE's coded rig view lists GSF C.R. LUIGS as DS (drillship), not JU. No alias or jack-up classification is invented to place those nine records into this subset. The 8,831 ft jack-up screening case is covered by an offline test; it is not a claim that such a retained source row exists.

Type cross-checks use other BSEE records by RIG_ID_NUM, including APD descriptions and the Rig ID List. They test consistency between records, not independent physical inspection; current registry values may not describe a historical configuration. Agreement: 24,080; conflict: 0; unavailable: 14,412. Missing secondary evidence is not treated as agreement.

Release dates are not established: the inspected WAR, borehole and EOR main schemas do not supply them. Every release_date is empty and flagged. Reporting-period end and borehole total-depth date are not rig-release dates. Spud dates describe the borehole and may precede the report by years. These records cannot establish rig visits, utilisation, operating days, exposure or site-assessment suitability. Early years and historical name variants have incomplete coverage.

Exclusions (one reason per source record, in selection order): other_rig_type: 132,651, outside_year_range: 6,913, unmatched_rig_name: 192,100. No depth or cross-check flag removes an otherwise selected row. Counts reflect records, not unique wells or rigs.

Reproduction and retention

Raw archives remain outside Git under the configured BSEE_JACKUP_RAW_DIR, using the documented blobs/sha256/<first-two-hex>/<sha256>.zip external-data layout. This directory is the repository's external data root within the shared data store; no machine location is embedded in this release. The raw files exceed the repository file-size limit and are not committed. They remain public BSEE downloads, but a later download at the same URL may differ; digest-matched retained blobs are needed for exact reproduction.

uv run --no-project python scripts/bsee/build_jackup_activity.py --raw-dir "$BSEE_JACKUP_RAW_DIR" --output-dir "$BSEE_JACKUP_OUTPUT_DIR"
uv run --no-project python scripts/bsee/build_jackup_activity.py --raw-dir "$BSEE_JACKUP_RAW_DIR" --reuse-manifest data/modules/bsee/jackup_liftboat_activity/manifest.json --output-dir "$BSEE_JACKUP_OUTPUT_DIR"
uv run --no-project python scripts/bsee/build_jackup_activity.py --verify-only --output-dir data/modules/bsee/jackup_liftboat_activity

Use a new raw directory for a download and a new output directory for regeneration. No existing raw or release file is overwritten. Offline tests: tests/unit/bsee/data/test_jackup_activity.py and test_jackup_activity_release.py.
