# LT reserves + discovery table (`lt_reserves_discovery.csv`)

Curated per-development BOEM recoverable reserves + discovery/first-production
dates for the 11 Lower Tertiary developments (issue
[#847](https://github.com/vamseeachanta/worldenergydata/issues/847)).
Generated by `scripts/field_development/build_lt_reserves_discovery.py` —
regenerate after a refresh with:

```
uv run python scripts/field_development/build_lt_reserves_discovery.py
```

## Sources (free, authoritative)

| Data | Source | Vintage |
|---|---|---|
| Original/Remaining BOE reserves, cumulative production | BOEM Reserves Inventory Program, annual **Table 4** (`2023 Tables xlsx Public.zip`, `estimated2023` page) | 31-Dec-2023 |
| Discovery + first-production dates | BSEE Deepwater Qualified Fields (`DeepQualRawData.zip`, weekly scheduler cadence) | rolling |
| Development → `FIELD_NAME_CODE` bridge | `config/input/lt_field_name_codes.yaml` (committed, reviewed) | static |

## Columns

- `DEV_NAME`, `FIELD_NAME_CODES` — development and its BOEM field code(s)
  (`+`-joined for multi-field developments: Cascade+Chinook, Jack+Saint Malo).
- `RESERVES_BOOKED` — `N` when the development is absent from the vintage:
  post-vintage first oil (Anchor 2024, Shenandoah 2025) or pre-FID
  (Kaskida, North Platte, Tiber). Rows are kept with NULL reserves.
- `BOEM_ORIG_RESERVES_MEAN_MMBOE`, `BOEM_CUM_PROD_MMBOE`,
  `BOEM_REM_RESERVES_MEAN_MMBOE` — Table 4 MEAN estimates, summed across the
  development's field codes. Units MMBOE (oil + gas BOE, not oil-only bbl).
- `DISCOVERY_DATE`, `FIRST_PROD_DATE` — ISO dates. First production prefers
  the **field-level** `FLD_FIRST_PROD` over the per-lease minimum of
  `FIRST_PROD_DATE` (the per-lease column can post-date field first oil by
  years — e.g. Buckskin field 2019-06 vs a 2026 lease).
- `SOURCE_*`, `RESERVES_VINTAGE`, `ACCESS_DATE` — citation columns.

**STOIIP is intentionally absent**: no government STOIIP source exists;
operator/announced figures remain a separately-cited column elsewhere
(owner decision on #847, 2026-07-06).

## Discrepancies (`lt_reserves_discrepancies.csv`)

Emitted whenever |BOEM − operator-announced| / operator > 20 % (announced
figures: Anchor 440, Jack St Malo 500, Stones 250 MMboe). Current vintage
flags **Stones: BOEM 128.3 vs operator 250 MMboe (−48.7 %)** — a substantive
input for the World Oil April 2026 Table 4 conversation. Jack St Malo
(BOEM 550.6 vs 500) is within 10 % and does not flag.

## Annual vintage bump (procedure)

1. New vintage appears at `data.boem.gov/Main/HtmlPage.aspx?page=estimated<YYYY>`.
2. Update the `fieldreserves_tables` `DatasetSpec` in
   `packages/worldenergydata-bsee/src/worldenergydata/bsee/data/refresh/url_registry.py`
   (URL year + `expected_bins` sheet slugs) and the pinned values in
   `tests/unit/field_development/test_lt_reserves_discovery.py::test_known_answer_real_2023_vintage`.
3. `uv run python scripts/refresh_bsee_all.py --dir fieldreserves_tables --force`
4. Regenerate this table; review the discrepancy CSV; update `VINTAGE` in the
   builder.

Related future sources (field monthly production, per-field reserve history
1975–2023, older vintages): [#855](https://github.com/vamseeachanta/worldenergydata/issues/855).
