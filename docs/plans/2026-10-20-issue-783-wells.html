Country wells input plan

The implementation will supply per-well inputs for FDAS without inferring active drilling days from milestone dates.

Revision history

RevisionDateChange and reason
12026-10-20The initial scope will separate well metadata from drilling activity to preserve the existing day-basis rule.

Scope and verification

  1. A country-neutral wells contract will validate identities, development assignments, nullable spud dates and water depths.
  2. A DataVic adapter will read complete local WFS GeoJSON exports, retain their digest, and require explicit development links and depth units.
  3. An activity allocator will split supplied, non-overlapping active drilling intervals at calendar month boundaries. It will expose incomplete well coverage as NOT_EVALUATED and refuse cashflow export in that state.

Tests will precede implementation and will cover invalid identities, missing dates, unknown units, duplicate records, truncated exports, interval overlap, leap days, year boundaries, missing coverage and nonzero drilling CAPEX.

Basis

DataVic WFS DescribeFeatureType (observed 2026-10-20) will govern source field names. The existing FDAS CashflowEngine.calculate_drilling_capex method will govern multiplication of activity days by a caller-supplied daily rate. Expected allocations will follow independent calendar counts in test docstrings. No default duration, rate or engineering acceptance limit will be introduced.

Adversarial plan assessment

The design will guard against treating rig release as a drilling endpoint, assigning fields by name similarity, assuming water-depth units, double counting overlapping intervals, and admitting partial coverage to cashflow. It will avoid an FDAS dependency on BSEE or Australia. Cross-provider review will remain pending for the draft pull request because this execution will not call other models.
