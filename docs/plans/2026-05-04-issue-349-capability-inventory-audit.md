## Risks and Open Questions

- **Risk:** The 2026-04-26 overnight matrix was generated without subprocess execution; some module presence claims may have been inferred from partial inspection. The audit script must re-derive all flags from live filesystem state to avoid carrying forward stale inference.
- **Risk:** `MODULE_INDEX.md` uses backtick-quoted names in Markdown tables — the parser must handle multi-word cells and avoid false-matching code examples in the "Agent Quick Reference" section.
- **Risk:** `data/catalog.yaml` top-level keys differ in naming from src package names in some cases (e.g., `eia_us` in manifest vs potential `eia` key in catalog) — the parser needs a normalization map for known aliases.
- **Risk:** GTM tier assignment is statically embedded from the 2026-05-04 review. If #364 lands a machine-readable tier file before this issue closes, the script should load from that file instead of the hardcoded map.
- **Open:** Should the script also check `tests/` coverage per module (test file present Y/N) as a fifth column? The issue body calls for it but the deliverable spec omits it. Flag for user during approval.
- **Open:** Deliverable location: issue body specifies `docs/reports/2026-04-26-worldenergydata-capability-readiness-matrix.md` as the output; this plan targets `docs/gtm/capability-inventory.md` (per user brief). These are separate artifacts — the 2026-04-26 report already exists; this issue closes by creating the new `docs/gtm/` surface. Confirm this is the intent.
