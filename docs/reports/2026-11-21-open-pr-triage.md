## Method and criteria

- Data come from `gh` (pull request metadata, issue comments, reviews and check runs) and from git against the snapshot of main. `git merge-tree --write-tree` gives the conflict set and shows whether merging would change main. `git merge-base --is-ancestor` and `git for-each-ref --contains` show whether a later branch carries a head. Main's version of each changed file is compared byte for byte.
- **MERGE**: a second-provider review passes at the current head; every required check (Lint, Check Sensitive Files, Security Scan, GitGuardian Security Checks, Test (PR gate)) succeeded at its latest run; merge-tree against main is clean.
- **ONE-FIX**: one blocking item or one conflict, named in the table. Where a review lists several findings that one fix round addresses, the row says so.
- **CLOSE**: superseded, already on main, obsolete, or carried in full by a later open PR. Each CLOSE pull request carries one comment with the evidence and the line "Proposed for closing; not closed." No pull request is closed and none is merged.
- **NEEDS-OWNER**: a scope or engineering decision; the table names it.
- Check state uses the latest run of each check name. `statusCheckRollup` also keeps superseded runs, and counting those overstates failures.
