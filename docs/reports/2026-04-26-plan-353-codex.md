**Missing Tests**

- Import-sentinel test proving `worldenergydata.scheduler.cli` import does not import scheduler job adapters.
- Test proving scheduler no-arg/help path exits without constructing `BseeRefreshJob`, `SodirRefreshJob`, etc.
- Test proving `refresh_bsee_all.py --help` avoids both `pandas` and `requests`, not only pandas.
- Test preserving `cmd_status(jobs=[mock])` and `cmd_run_job(..., jobs=[mock])` compatibility after lazy refactor.
- Test proving `status` lists configured jobs without instantiating runtime job adapters, if the metadata-registry design is used.

**Scope Creep Concerns**

- “scheduler status should avoid work not required for status registration if feasible” is underspecified and could turn into a scheduler architecture rewrite.
- “Document operational workaround” for uv can become a catch-all unless classification probes are defined.
- “Verify only `scheduler/jobs/*.py`” may expand into many job refactors if import-time side effects are found.

**Weakest Assumption**

The weakest assumption is that the remaining scheduler `status` latency is primarily eager job import/instantiation. If false, a lazy job registry may not bring `status` under 10s, and the implementation will add complexity without meeting the issue acceptance threshold.

**Most Likely Implementation Failure Mode**

A worker makes `ALL_JOBS` lazy for help, but `status` still imports all job modules to list jobs, or loses job completeness by only listing config entries. Either outcome misses part of the acceptance criteria.

**Most Likely Test Gap**

Tests assert subprocesses complete under a timeout but do not prove the absence of heavyweight imports or network/download setup. That can pass on a warm machine and fail elsewhere.

**Future Issues Suggested**

- Separate uv environment-resolution investigation with explicit uv/cache/lockfile probes.
- Scheduler job metadata registry cleanup, if broader than #353.
- Import-time budget audit for all scheduler job adapters.
