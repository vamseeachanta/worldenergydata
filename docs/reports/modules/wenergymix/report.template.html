1. Executive Summary

The energy mix module is an offline data pipeline for country/year offshore-wind observations. Analysis is performed to determine its documented behavior and numerical evidence; key results are summarized below.

  • The published synthetic example converts @@metric:alpha_gwh@@ GWh to @@metric:alpha_mwh@@ MWh.
    • The result equals the energy-unit conversion in Section 5. It supports use of the documented conversion interface on this example; source-observation accuracy remains not evaluated.
  • Unavailable generation remains unavailable, and reported zero remains @@metric:zero_mwh@@ MWh.
    • The nonnegative measurement boundary is @@metric:zero_mwh@@ MWh. Missing generation cannot be interpreted as a measured zero or inferred from capacity.
  • Use on source observations requires an established data basis.
    • Source units, observation vintage, coverage, accuracy and reuse rights require evidence before an engineering conclusion is drawn. The module supplies no national energy shares, generation forecast or equipment operating envelope.

The example and its limitations are developed in Section 6 using the documented public repository example. Required next actions are given in Section 8.

2. Introduction and scope

Caller-normalized observations are validated and selected without network access. Offshore-wind capacity and generation are carried as distinct quantities with source citations.

The main workflow covers loading a normalized comma-separated-values table, selecting country/year records, converting generation to megawatt hours, and emitting a manifest for the original input. Public Python functions and a command interface are documented in Section 9.2. The International Renewable Energy Agency is abbreviated IRENA; its name identifies the intended source family and does not establish that the example contains agency observations.

2.1 Not covered

Native-source ingestion, automated retrieval, other generation technologies, national totals, energy-mix percentages, capacity factors, dispatch, emissions, economics and time-series forecasting are outside this workflow. No physical plant, vessel, mesh or load model is solved. The package name does not establish those capabilities (implementation; query contract).

3. Basis and criteria

The calculation basis is the published synthetic offshore-wind example and the International System of Units. Numerical criteria are separated from source-data qualification.

3.1 Numerical basis

The conversion is defined by the BIPM SI Brochure, ninth edition, version 4.01, Section 3, Table 7. The reference is the prefix ratio, not a fit to observations. Exact decimal equality is required for the hand-worked conversion anchors. Display consistency is checked with an absolute tolerance of 10−12 in each displayed unit; this is a numerical checking tolerance and assigns no measurement uncertainty (report checks).

3.2 Input boundaries

The loader accepts at most @@metric:max_bytes@@ bytes and calendar years from 1960 through the current Coordinated Universal Time year, @@metric:clock_year@@ at preparation. Both are software policies in the loader, not published source coverage. Measurements are finite and nonnegative; the lower bound is @@metric:zero_mwh@@ in the declared unit. At least one of capacity and generation is required per row. No physical upper measurement limit or accuracy criterion is supplied.

Real-source readiness is not evaluated by successful parsing. Source authenticity, units, permissions, geographic definitions, completeness and intended-use eligibility require separate evidence. Unavailable values are distinguished from true zero throughout this report. No missing engineering input is replaced by an assumed observation.

4. Inputs and outputs

The input is an explicitly normalized byte table with declared units. A list of validated records, selected table bytes and a provenance manifest are returned by separate interfaces.

The table has @@metric:column_count@@ ordered columns: country, optional alphabetic country code, year, technology, capacity in megawatts, generation in gigawatt hours, source address and citation. The exact column names are given in Section 9.2. Technology is exactly offshore wind. Country names and citations are nonempty; surrounding whitespace is rejected. Country codes are blank or uppercase three-letter strings; registry membership is not checked.

Duplicate country/year keys and inconsistent country/code mappings are rejected. Year bounds in a query are inclusive. Country matching is case insensitive, repeated country selections do not duplicate observations, and input order is preserved. An empty selection returns a header without observations. Invalid unselected rows still fail validation (query implementation).

The loader returns Python floating-point measurements or a missing-value sentinel. The query rereads validated source text and preserves supplied decimal digits; megawatt-hour output uses decimal multiplication and a renamed generation column. Capacity remains in megawatts. Converted output is a distinct contract and cannot be reloaded through the original gigawatt-hour header contract.

The manifest records the original input digest, size, row count, declared units, supplied citations and synthetic status. A real export requires a caller-supplied UTC retrieval time and terms provenance; these assertions are not authenticated by the emitter. Query output does not carry a new manifest. The original manifest does not identify filtered or converted bytes (manifest interface).

5. Theory and method

Energy units are converted by a decimal prefix ratio, and records are selected by explicit keys. Capacity is not converted into generation.

5.1 Energy conversion

Let EG denote the numerical generation value in GWh, EM its numerical value in MWh and k the conversion coefficient in MWh/GWh. The equation is EM = k EG, with k = 109/106 = @@metric:conversion@@ MWh/GWh. Giga and mega are defined in Section 3, Table 7 of the SI Brochure; the hour is unchanged. The symbols GWh and MWh mean gigawatt hour and megawatt hour. MW denotes megawatt, a unit of power.

This relation rescales a supplied energy quantity; it introduces no efficiency, operating hours, availability or capacity-factor coefficient. Blank generation is not multiplied. The decimal result is written exactly or conversion fails when exact representation is unavailable (query implementation).

5.2 Data model and boundaries

The whole input is checked before selection. Source addresses and citations are preserved, but no source request or independent observation reconciliation occurs. The optional loader serialization changes numeric text through floating-point parsing; exact supplied decimal text is preserved by the direct query route (loader; query).

7. Validation evidence

Repository evidence is examined through existing offline tests and report-specific numerical checks. These checks establish behavior for their stated cases and do not qualify real observations.

Loader tests exercise the fixture round trip, malformed headers and measurements, duplicate keys, country-code consistency, provenance syntax, input preservation, manifest equality and refusal of live fetching. Query tests exercise inclusive selection, empty outputs, validation of excluded rows, missing versus zero generation, exact conversion, extreme decimal exponents, supplied precision and command output protection.

The published conversion example is already demonstrated in the query documentation. The only committed observation dataset used here is explicitly synthetic, and its saved manifest is available. A native-source comparison dataset, measured benchmark and real-source accuracy criterion are not established by the inspected module evidence (fixture; published query example).

Report checks assert the hand-worked conversion values @@metric:alpha_mwh@@ MWh, @@metric:beta_mwh@@ MWh and @@metric:zero_mwh@@ MWh with exact decimal equality. Separate consistency checks rebuild the document and compare marked numerical values with module returns, check missing cells, recompute the headline from displayed inputs and preserve source bytes. These are consistency checks rather than a second implementation of the data pipeline.

8. Limits and recommendations

The demonstrated capability is bounded by the normalized input contract and synthetic evidence. The following actions address the missing basis before broader use.

8.1 Limits of use

Native export headers, current source access, observation accuracy and source reuse permission remain not evaluated. The live-fetch function refuses locally without transport. Its recorded access message is historical and supplies no evidence of present source availability. No live source probe is made for this report (source-access record).

The loader uses floating-point parsing for validation and records; it assigns no measurement precision. Extreme small nonzero text can lose magnitude in a loaded record, although direct query conversion retains the supplied decimal spelling. Country-code syntax does not establish official membership. An HTTPS-shaped address and nonempty citation do not authenticate a source. The command checks destination collisions, but paired table and manifest writes are not a transaction (loader; query; command interface).

8.2 Recommendations

Before source observations support an engineering comparison, obtain a permitted source export with readable terms, preserve its original bytes and reconcile normalized headers, units, country keys and vintage against the source. Record uncertainty and completeness criteria appropriate to the decision; these are required inputs, not values supplied by this module (remaining source evidence).

For exact decimal energy text, use the direct query route rather than a loader-to-serializer round trip. Preserve the original manifest separately and record a new digest for any selected or converted output. Add a source-backed benchmark after accuracy and reuse evidence are established. Define paired-output failure behavior before automated use relies on both table and manifest being present (query contract; documented failure modes).
