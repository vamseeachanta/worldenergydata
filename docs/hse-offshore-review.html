Summary

Inputs and method

The input is the existing external modules/hse/offshore/offshore.sqlite database. No network retrieval occurs. A single explicit SQLite read transaction captures the event, source, external-link and gate rows with their canonical dataset digest. A concurrent writer cannot bind new bytes to an older worklist.

Report-only CLI calls open SQLite in read-only mode, without schema migration. A missing database raises an error and creates no directory or empty collection. The same path is available as OffshoreImporter(database, read_only=True).

Canonical count is the number of distinct event IDs across standalone events and external links. Multiple links for one event count once. Pilot source count uses distinct public authorities for the pilot event; cached rows and repeated documents from an authority do not increase it. A recorded pilot gate identifies the pilot; without one, a sole canonical event is used. An ambiguous pilot worklist requires --pilot-event-id.

Candidate intake changes the dataset digest after pilot approval. The pilot receipt is therefore reported as a historical gate maintained by the importer, rather than compared with the current whole-dataset digest. Reconciliation and bulk receipts must match current evidence. These diagnostics do not change the importer's acceptance rules or authenticate any receipt.

For bulk review, canonical IDs are ranked by ascending hexadecimal SHA-256(dataset_sha256 + ":" + event_id). The first ceil(N / 10) IDs form a reproducible minimum worklist. For pilot review, all stored sources for the selected pilot are included. This is a deterministic checklist, not a claim of unbiased statistical sampling. More records may be reviewed. No engineering equation or physical coefficient is used.

A record linked to an existing dataset has event: null and retains all stored external identities and annotations. The canonical dataset remains the authority for fields absent from that link. Every stored source includes its existing citation and licence; cached evidence remains visible as cached.

Commands

Run in the repository's Python environment with an external data root and an output file outside the checkout:

python scripts/import_offshore_hse.py --data-root "$WED_DATA_ROOT" --readiness
python scripts/import_offshore_hse.py --data-root "$WED_DATA_ROOT" --review-worklist pilot
python scripts/import_offshore_hse.py --data-root "$WED_DATA_ROOT" --review-worklist bulk > "$REVIEW_OUTPUT"

The Python interfaces are collection_readiness(importer) and build_review_worklist(importer, stage="bulk") from worldenergydata.hse.offshore_review. The CLI's existing intake and approval options run before these reports when combined in one invocation. Each report carries its own digest; compare reports only when their digests agree.

Worked example: inputs, method and answer

examples/offshore_hse_review.py defines one synthetic event and one synthetic source, with an explicit text inventory. Its source URL is a placeholder, not evidence of an official incident. Use a new output directory:

python examples/offshore_hse_review.py --output-dir "$EXAMPLE_OUTPUT"

The example saves input.json, ingests it twice, prepares a pilot worklist and reads back answer.json. The independent count is one distinct event plus zero new events on repeat intake, giving one canonical event and one source. One public authority is below the three-authority pilot criterion, and one event is below the 50-event criterion. Independent receipts and consumed indexes are absent, so those checks are NOT_EVALUATED and bulk_admitted is false. The minimum bulk review count is ceil(1 / 10) = 1; the pilot worklist contains that sole event. No receipt is manufactured.

The tests write out the independent rounding examples: N = 1, 9, 10, 11, 49, 50, 51 gives ceil(N / 10) = 1, 1, 1, 2, 5, 5, 6. Additional cases check database-byte preservation, concurrent source insertion, linked identities, cached authorities, malformed receipts and actual bulk receipt submission through the existing importer.

Limits and next collection slices

Source truth, privacy, rights, freshness and canonical-index completeness are not established by counting rows or preparing a worklist. The original reviewed-text inventory is not retained by the importer; a reviewer must inspect all stored text and the permitted public sources. A falsely approved inventory can contain a personal name. A receipt's role string does not authenticate an independent reviewer. None of these outputs qualifies data for engineering use.

Next collection work requires the third verified pilot authority, recoverable candidate evidence, complete HSE and marine-safety exports and independent source review. Access blocks shall not be bypassed. These remain collection requirements under issue 1325, not successful results of this software example.
