Open metocean observations and source register

The existing metocean package retains NDBC yearly wave observations, original response digests and a long-form Parquet store. The source register records observed access and publisher terms. This release establishes an archive observation workflow; current conditions, complete regional coverage and design conditions are not established.

Findings

The package resource worldenergydata/metocean/data/source_register.json is the authoritative register. The existing extrapolation catalogue reads its compatibility records from that resource. Those representative locations are not verified station metadata and shall not select nearby measurement stations.

Only NDBC yearly standard meteorological records are enabled in the update service. WVHT is retained as wave_height_m in metres; DPD is retained as wave_period_s in seconds with period_kind=dominant. No peak-period conversion is applied. The NDBC .spec probe contains wave summaries; it does not establish spectral-density ingestion.

What this means for our work

Configure a data root outside the checkout. Raw responses belong under raw/source/station/digest.txt; normalised partitions belong under normalized/source/station/digest.parquet. The manifest records URL, UTC retrieval time, bytes, SHA-256, publisher terms and relative cold-store paths. A local retained copy does not establish a backup replica.

python -m worldenergydata.metocean.cli update --config data/modules/metocean/first_set.json --data-root ../metocean-data

The example data root is a relative external location to be selected by the operator. The supplied configuration ends at completed archive years. An ordinary repeat requests no completed resource again. Explicit --refresh checks publisher revisions using retained ETag or Last-Modified headers when available. A new version remains separately traceable; statistics shall consume one active complete version per requested URL.

Requests are anonymous and name the public repository in the User-Agent. Requests start at least 1.1 seconds apart per host. The transport allows at most 2,000 requests per host and 2 GB per run, and at most 300 MB per response. Temporary HTTP errors receive bounded back-off of at least 60 seconds. Refusals terminate further requests to that publisher for the run. These are implementation limits, not claims about publisher quotas.

The scheduler's archive configuration invokes the same update service. The existing forecast configuration remains compatible. No recurring schedule is installed by this release.

Statistics and validity

Statistics are arithmetic on retained source rows at their actual UTC timestamps. Two-digit years are interpreted as 1900 plus the reported year. Missing tokens, sentinel values, non-finite values, negative heights and non-positive periods are retained as null with a missing quality flag. Repeated timestamps remain distinct source rows. No regular-grid interpolation is applied.

For sorted values, quantiles use zero-based rank p(n - 1) and linear interpolation between adjacent ranks. Tables cover all months, each calendar month and October through March. The dominant period paired with the 95th-percentile height is sampled within the closed height band of that value plus or minus 0.25 m. A tied mode selects the lowest reported period. Empty groups contain zero counts and null statistics.

The percentile tables are derived observations, not return-period estimates or design values. Differences from the consultancy's Gulf of Mexico buoy wave statistics require reconciliation of the retained records and validity conventions; they shall not be attributed to archive revisions without evidence of both versions.

The retained archive contains 177 yearly files. Original-row and unique-timestamp tables are published separately in data/modules/metocean/. Repeated valid timestamps account for count differences of 209, 1,563, 912 and 46 for stations 42001, 42002, 42003 and 42040 respectively. The unique-timestamp comparison reproduces all supplied valid counts, height percentiles and paired-band counts. Dominant-period results reproduce the supplied values at one decimal place; the tables preserve reported precision.

These counts are this implementation's arithmetic from first_set_manifest.json. The comparison keeps the first valid height per UTC timestamp in ascending archive-year order and its paired period from the same row. Conflicting duplicate pairs are counted in the manifest. Use summarize_observations(rows, unique_timestamps=True) for this explicit comparison; the default retains original rows.

Adding a source

Add a publisher-backed register row with units, time coverage, cadence locators, access requirements, a small observed request and publisher reuse terms. Re-open the terms page and verify its quotation before enabling the source. Extend a client on the existing base class; use the bounded transport and normalised variable conventions. Add recorded or explicitly synthetic fixtures, prohibit real connections in unit tests, and test digest verification, UTC handling and repeated-run behaviour. A successful HTTP response is insufficient to enable a parser.

New archive unit-test payloads are handwritten synthetic records in the publisher's format. They contain no downloaded observation data. Live probes are skipped by default with a stated reason; METOCEAN_LIVE_TESTS=1 opts in to the bounded publisher requests.

Not found / not verified

Regional sources without an observed data request remain disabled. Australia AUSWAVE requires registered access; its terms quotation could not be confirmed on re-fetch. The Brazil terms quotation was not found on final re-fetch and was removed from confirmed findings. The NHC best-track page and NDBC current directory returned HTTP 403. No alternate access route was attempted. A complete no-account hindcast product, West African national data service, spectral-density parser, current parser and tropical-cyclone archive integration are not established.

The first-set configuration identifies the nearest station within the fetched CO-OPS metadata response by great-circle distance from NDBC-published coordinates. Its metadata digests and candidate count make that selection reproducible; proximity does not establish product availability or common hydrodynamic conditions. A live water-level update is not implemented. The current calendar year and real-time revisions are not part of the yearly snapshot update. Optional legacy statistics tests require a dependency not present in the isolated test environment. No design values from licensed standards or proprietary hindcasts are consumed.
