Configuration and usage

The reusable package is worldenergydata.modules.state_regulators.fetch, following the Colorado ingest's urllib and SHA-256/UTC provenance conventions. Cache location is explicitly supplied as FetchConfig.cache_root or through STATE_FETCH_CACHE_ROOT; there is no default path. The operator shall select a data-disk location. contact is a required configuration value for the descriptive User-Agent. No personal address is supplied.

config = FetchConfig.from_env(contact=approved_contact)
# Populate checks only after reading and recording the source terms.
fetcher = Fetcher(config, recorded_terms_checks)
projection = fetcher.run(planned_urls, dry_run=True)
# Review the projection, permissions and selected bulk route before execution.
results = fetcher.run(planned_urls)

TermsCheck records the exact source origin, terms URL, UTC retrieval/check date and explicit bulk-access permission. Missing or denied permission refuses all uncached network collection, including preflight. Validated records are retained as terms-checks.json before requests and in each fetched object's provenance. The library records caller-supplied decisions; it does not infer permission from a successful response or perform terms review.

choose_route prefers caller-verified official bulk candidates and logs any crawl selection, including available bulk alternatives. It does not discover endpoints or crawl. Redirects are refused; any redirect destination requires its own explicit source permission and URL selection. Every attempt is identified, timeout-bound, paced and charged against a per-host budget. An uncached first request serves as the reachability preflight and retains its payload, so there is no extra probe. A reachability failure includes the executing machine name only in its runtime exception.

objects/<sha256> contains payload bytes. URL-keyed records/ sidecars retain source URL, UTC fetch timestamp, response headers, SHA-256, size and the terms decision. Payload digest and size are verified on readback. progress.json retains completed URLs, request reservations and cooldowns. Atomic writes permit restart after interruption; corrupted cache evidence stops rather than silently becoming valid input. One writer per cache root is required; concurrent writers are unsupported. Payloads are read into memory, so this layer is intended for bounded objects; streaming large archives is future work.

The offline projection reports unique uncached requests, cached URLs, maximum retry attempts, baseline wall-clock estimate and terms status. Estimates exclude response latency, future header changes and retry delays; unknown vendor windows use configuration. Exhausted budgets stop collection for later resume. HTTP 429 retries are bounded and honor Retry-After; HTTP refusals stop the run.
