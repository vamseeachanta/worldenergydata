Configuration and usage

The reusable package is worldenergydata.modules.state_regulators.fetch, following the Colorado ingest's urllib and SHA-256/UTC provenance conventions. Cache location is explicitly supplied as FetchConfig.cache_root or through STATE_FETCH_CACHE_ROOT; there is no default path. The operator shall select a data-disk location. user_agent is required configuration, with the repository URL as contact in the (+URL; purpose) form.

config = FetchConfig.from_env(
    user_agent="public-records/1.0 (+https://github.com/vamseeachanta/worldenergydata; public records research)"
)
# Populate checks only after reading and recording the source terms.
fetcher = Fetcher(config, recorded_terms_checks)
projection = fetcher.run(planned_urls, dry_run=True)
# Review the projection, permissions and selected bulk route before execution.
results = fetcher.run(planned_urls)

TermsCheck records the exact source origin, terms URL, UTC retrieval/check date and explicit bulk-access permission. Missing or denied permission refuses all uncached network collection, including preflight. Validated records are retained as terms-checks.json before requests and in each fetched object's provenance. The library records caller-supplied decisions; it does not infer permission from a successful response or perform terms review.

choose_route prefers caller-verified official bulk candidates and logs any crawl selection, including available bulk alternatives. It does not discover endpoints or crawl. Redirects are refused; any redirect destination requires its own explicit source permission and URL selection. Every attempt is identified, timeout-bound, paced and charged against a per-host budget. An uncached first request serves as the reachability preflight and retains its payload, so there is no extra probe. A reachability failure identifies the build host by role in its runtime exception.

objects/<sha256> contains payload bytes. URL-keyed records/ sidecars retain source URL, UTC fetch timestamp, response headers, SHA-256, size and the terms decision. Payload digest and size are verified on readback. progress.json retains completed URLs, request reservations and cooldowns. Atomic writes permit restart after interruption; corrupted cache evidence stops rather than silently becoming valid input. One writer per cache root is required; concurrent writers are unsupported. max_response_bytes defaults to 5 MiB (5,242,880 bytes), bounding memory for small records; large archives require a future streaming implementation. Advertised lengths above the cap are refused before reading; otherwise at most cap + 1 bytes are read. Oversized responses are never cached and still consume an attempt.

max_sleep_seconds defaults to 300 seconds and must be finite and positive. Before a request, a longer cooldown raises BudgetExceeded with the host and UTC resume time, without sleeping. The original server-requested time remains persisted across restarts; the cap never shortens it. This covers Retry-After, standard rate limits and vendor headers. Invalid or unrepresentable header values retain fallback pacing.

Invalid JSON or malformed budget state in progress.json raises a named cache-integrity error. Nothing is deleted or overwritten automatically. The operator may preserve the file by moving it aside explicitly, then wait one full budget window before resuming with empty budget state. Cached objects and per-URL records remain unaffected and are still verified on read. Damaged per-URL JSON records also raise a named integrity error.

Data retrieved under an earlier recorded permission remains readable from cache after permission is withdrawn. That cache-hit path makes no network request; purge is an explicit operator action. Uncached URLs still require permission.

The offline projection reports unique uncached requests, cached URLs, maximum retry attempts, baseline wall-clock estimate and terms status. Estimates exclude response latency, future header changes and retry delays; unknown vendor windows use configuration. Exhausted budgets stop collection for later resume. HTTP 429 retries are bounded and honor Retry-After; HTTP refusals stop the run.

The original fetch implementation made no regulator request, crawl or volume run. Indiana wiring, actual recorded terms checks, current reachability observations and an authorized real run remain future work. No bulk data is committed.

Configured collection command

config/state_regulator_fetch.example.json is an offline example, with synthetic operating inputs and no terms permission. All pacing, timeout, retry, sleep and payload limits are required in this command's configuration; none is inferred from undocumented vendor behavior. Supply an absolute data-disk directory through STATE_FETCH_DATA_ROOT and set STATE_FETCH_EXECUTION_ROLE=regulator-fetch in the deployment that has been assigned source collection. Replace the example contact URL with a maintained public contact URL.

python -m worldenergydata.modules.state_regulators.fetch.job config/state_regulator_fetch.example.json
# After source terms have been reviewed, recorded and permitted:
python -m worldenergydata.modules.state_regulators.fetch.job config/state_regulator_fetch.example.json --execute

The first command makes no HTTP requests. It reports unique pending requests, cached URLs, the selected route, maximum attempts, estimated time and permission status. It may create empty cache directories and reads retained objects to verify integrity. The second command refuses the example because its permission list is empty.

The execution role must match before cache creation. This is a deployment assertion, not hardware attestation: the deployment controls the environment variable. Actual source reachability is checked by the first budgeted request; a connection or name-resolution failure stops the plan without retrying or starting later URLs. Cached payloads need no reachability probe. Current PDMS reachability remains NOT_EVALUATED; the historical observations above must not be treated as a current measurement.

The resolved cache directory must be inside the configured absolute storage root. Symlink escapes and unresolved variables are refused. This checks placement, not disk identity, free capacity or concurrent filesystem replacement; the deployment must provide a stable data directory. Run only one writer per cache root.

List reviewed official archive, ArcGIS REST or shapefile URLs under bulk_urls and record crawl page URLs under crawl_urls. The first bulk candidate is selected when available. use_crawl=true requires crawl URLs and logs the available bulk alternatives. Endpoint discovery remains a human source-review step; this command does not scrape to discover routes. Before executing any uncached URL, the complete plan must have matching recorded TermsCheck entries. A terms record contains origin, terms_url, checked_at (UTC) and an explicit Boolean bulk_allowed. Successful HTTP access never supplies permission.

Worked example: inputs, method and answer

All numbers in this example are synthetic operator choices, not measured regulator limits. Inputs: three unique uncached URLs on one origin; spacing 2.0 s; at most three attempts per 10.0 s; one retry per URL; no retained attempts or server cooldown. The example also chooses a 5.0 s timeout, 30.0 s sleep cap and 1024-byte payload cap; these bound execution and do not enter the no-retry estimate.

Independent hand calculation: request starts occur at 0.0, 2.0 and 4.0 s, so the pacing-only estimate is T = (N - 1) × spacing = (3 - 1) × 2.0 = 4.0 s. There is no trailing sleep after the last request. Maximum attempts are A = N × (1 + retries) = 3 × (1 + 1) = 6. A fourth URL starts at 10.0 s: after starts at 0.0, 2.0 and 4.0 s, the rolling window releases the first reservation at 10.0 s. After a completed run, a restart reports zero pending requests and makes zero requests. The offline example reports terms_permitted=false; tests grant permission only to a local fake server.

Method source: these schedule and attempt equations follow directly from counting the configured gaps and attempts; the independent arithmetic is also written in tests/unit/state_regulators/test_fetch_job.py. The projection excludes response latency, future server limits, retry waits and later invocations needed after budget exhaustion. For multiple hosts, the sum of per-host projections is a conservative serial estimate, not a completion-time guarantee.

Protocol sources and limits

RFC 9110 (2022), section 10.2.3 defines Retry-After seconds or an HTTP date; section 10.1.5 defines User-Agent. RFC 6585 (2012), section 4 defines HTTP 429 and its optional Retry-After field. RateLimit Fields for HTTP, draft revision 03 (2022), section 5 describes the legacy RateLimit-Limit, Remaining and Reset fields handled here. This draft is a historical protocol source, not a claim of conformance to a current standard. Vendor numerator meaning, reset units and window duration remain unverified; configured fallback assumptions do not establish a safe source-specific rate. No source permission, fresh reachability measurement, legacy-ingest migration, streaming archive support or volume collection is claimed by these offline checks.
