Inputs, method and answer

The executable example uses three synthetic contracts for one synthetic field and one month. The oil inputs are 10.5 bbl, 2.5 bbl and an unknown volume. The method parses the year/month and native decimal values, retains contract identity, sums the known values only, and counts unknowns separately. The answer is a known subtotal of 13.0 bbl and one unknown; a complete field total is not established.

PYTHONPATH=src python examples/international_sources.py

The example is offline and contains no live production values. Its regression test compares the output with the hand calculation written in the test docstring.

Collection interface

from worldenergydata.international_sources.client import SourceClient

# Explicit operational choices, not engineering limits or source defaults.
client = SourceClient(timeout_seconds=20, max_bytes=1000000)
page = client.colombia_page("oil", limit=100, offset=0)
# page.complete is False; metadata.source_modified is the publisher's vintage.
# page.rows_evidence.raw_bytes is the original response for separate retention.
# No request is repeated or paginated automatically.

The byte and timeout limits are required caller inputs. JSON media type, response size, duplicate keys, non-finite numbers and dataset identity are checked before data is returned. HTML application shells fail validation even with HTTP 200. Reuse terms are exposed as evidence, not interpreted as blanket redistribution permission.

ANH's oil column description identifies barrels produced in the month. The gas column description identifies thousand cubic feet. Those native quantities are retained as bbl and Mcf, without scaling or daily-rate multiplication. Plain decimal text and the observed comma-grouped decimal format are parsed strictly; ambiguous group-only text, malformed separators and signed adjustments are rejected pending qualification. Missing volume columns are schema failures; null values stay unknown. Oil and gas are not joined, contracts are not combined, and missing water is never zero-filled.

Analysis and scheduler boundary

The existing country contract normalizes unified production columns for FDAS. These observations deliberately precede that contract: water coverage, cross-commodity joining, source completeness, well metadata, field crosswalks and fiscal inputs are not established. No empty or fabricated cashflow is emitted. Scheduler registration will require retained raw-data ownership, rights and freshness criteria, normalized coverage checks and the repository's source-refresh acceptance contract.

The shared source catalogue and domain-database index were unavailable in the inspected checkout. This note is task-scoped evidence, not a replacement catalogue; no authoritative source identity or new allocation registry is created.
