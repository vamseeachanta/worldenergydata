Pipeline screening acceptance and restoration

Revision 2 implements I-0248 in PR 1229. The retained observations describe a screening inventory. Installed dimensions, site transfer and stability acceptance are not established.

Selection and physical inputs

The explicit installed-status set is ACT, OUT, PABN and PREM. The service-state field records the published dictionary class. Selection is independent of the shared active-status helper and does not establish present operation. All other codes, including blanks and dictionary-undefined codes, are excluded and counted. Dictionary verification hashes the sorted, compact JSON code-to-meaning table, excluding ASP.NET hidden state.

The cited permit and location headers do not contain minimum water depth or burial design. Those fields and the depth-derived soil fallback are removed. Published zero permit lengths and MAOPs are treated as unknown, as their engineering meaning is not established. Retained source bytes are preserved. Route validation failures and route/permit length ratios below 0.67 or above 1.5 are listed in QA; values are not corrected.

wall_thickness_m requires a published dimension or a supplied dimensional table with source, rights and edition. Otherwise its tag is UNKNOWN:no_evidenced_wall. The separate hoop_yield_wall_at_assumed_smys_m is pD/(2SMYS), using nominal size as OD and assumed X52 at 358.53 MPa. It is not installed wall. It is a lower bound on installed wall only where installed SMYS does not exceed assumed SMYS. No design factor, corrosion allowance, mill tolerance or collapse check is included. No weight, D/t or stability calculation consumes this separate field as installed wall. The STD lookup preference is unused in the public build.

The clause quoted from memory in the decision is confirmed against 30 CFR §250.1002(a), Formula 1 and definitions of F, E and T, consulted 2026-10-17: internal design pressure includes FET, with F=0.72 submerged and F=0.60 riser. These factors are cited context and are not applied to manufacture an installed wall. The assumed 358.53 MPa remains the decision's value, based on the existing pipeline_safety.workflow:_DEFAULT_SMYS_MPA, rather than a material certificate or qualified dimensional table.

30 CFR §250.1751 describes decommissioning in place. The installed-status selection is the declared decision policy, not an inference that a proposal itself establishes completion of decommissioning.

Environmental qualification

A complete station-year requires finite positive Hs observations in at least 80% of distinct UTC calendar-year hours, including leap years, and at least 80% of June-November hours for the Atlantic basin. Subhourly duplicates cannot increase coverage. The Atlantic coverage region used for these Gulf inputs is explicitly bounded by 0–65° N and 100° W–20° E; outside that screening region only annual coverage applies. NOAA tropical cyclone climatology confirms the Atlantic season as 1 June–30 November. The claim that cyclone conditions govern these maxima remains an assumption; this inventory does not attribute individual maxima to cyclones.

The thresholds n≥10, T≤4n and 80% coverage are declared I-0248 policy; no standard clause is claimed. Hs10 requires ten complete maxima and Hs100 requires twenty-five. GEV fitting uses only qualified annual maxima. Each published estimate has n, distribution and named lower/upper 95% confidence bounds. The repository wrapper explicitly requests 0.95 uncertainty from metocean-stats 1.1.9; 1,000 backend bootstrap replicates use a fixed seed, with the prior random state restored. Missing, nonfinite or nonpositive bounds suppress publication. Four retained calendar years cannot qualify return levels. The observed maximum and its years remain distinct from a return level; its coincident observed period is retained. Marginal period extremes are removed.

The nearest station must have retained finite positive wave observations and be within an assumed 50 km screening radius. The same radius limits sediment matching. This is the narrower reading of the review; proximity does not establish site-transfer validity. Station depth is unknown unless an explicit depth observation is supplied: active-station XML elevation is not water depth. Texture dominance uses Sand, Mud and Gravel; Clay is a subset of Mud. Current is unknown. Wave direction is assumed coming-from, clockwise from north, route bearing +90°: the right-hand side following increasing route sequence. Friction and grade remain labelled assumptions.

Sources and terms

Every source and manifest input includes title, publisher, locator, retrieval time, digest and publisher terms. The BSEE copyright statement distinguishes federal material from third-party exceptions. The NOAA/NWS use statement allows lawful reuse with source credit, no implied endorsement and no derivative presented as an official product. The USGS title is usSEABED: Gulf of Mexico and Caribbean (Puerto Rico and U.S. Virgin Islands) Offshore Surficial Sediment Data Release, version 1.0. The retained gmx_extmeta.txt Use_Constraints in the DS 146 archive permits redistribution with metadata and source attribution. Source metadata remains attached to all derived exports.

Retained inputs and restoration

The full CSV is external: payload.path=full.csv with path_scope=external_destination describes the external destination basename; payload.blob is relative to the supplied store root. re_downloadable=false: a retrievable remote store and a second copy are not established. Public upstream addresses can change bytes and are not a digest-pinned backup. The maintainer must supply the retained input store matching the manifest; a fresh download is accepted only if its digest and byte count match. No remote retrieval is implied.

The build's --source-ledger is a JSON array. Each core entry requires file (the supplied basename), source_id, url, retrieved_at (UTC), bytes, sha256, title, publisher and terms_of_use with statement and url. Source vintage is always an object. HTTP status is always an integer. The committed source register can serve as this ledger: entries without file are retained NDBC histories and are ignored by core-input lookup. Histories use responses/<sha256(url)>.json, with a relative body locator into the same content-addressed store. Both the response metadata and pinned body are required for offline replay.

python scripts/bsee/build_pipeline_screening.py --permit-zip <external permit.zip> --location-zip <external location.zip> --station-xml <external ndbc-stations.xml> --sediment-zip <external sediment.zip> --status-dictionary <external status-values.html> --source-ledger <external ledger.json> --output <external output> --cache <retained store> --execution-record <external criteria.json> --offline
python scripts/bsee/fetch_pipeline_screening.py --manifest data/modules/pipeline/screening/manifest.json --store <retained store> --destination <external full.csv>

Schema, defaults, code and revision digests pin the execution criterion. Changing any of those requires a new execution record. Two offline builds must reproduce every output byte; restoration checks both payload size and digest. A successful process exit alone is insufficient: output readback and manifest verification establish the recorded result.
