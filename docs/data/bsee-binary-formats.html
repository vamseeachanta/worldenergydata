BSEE binary ingestion

The local ingest command converts the approved borehole, WAR, rig-fleet and directional-survey tiers to timestamped CSV or Parquet tables. The existing catalog remains the dataset registry. No network request or licensed solver is used by the command. Scope: issue 365, including the 10 June 2026 plan-review comment.

Execution and retention

make unpack-bsee BSEE_SOURCE_ROOT="$BSEE_SOURCE_ROOT" \
  BSEE_INGEST_ARGS="--current-root $BSEE_CURRENT_ROOT --trust-pickles"

# Optional: --dataset borehole (repeatable), --date 2026-11-13,
# --format parquet, --chunk-size 10000, --encoding utf-8
# Override BSEE_INGEST_PYTHON when using a virtual environment.

The source root must hold the existing binary and ZIP tiers; cached raw archives are also supported. No source is downloaded or modified. Sources must already be mounted or cached. The project-root override supports isolated runs. The current-root option selects the existing CSV tier independently of the source root. Every requested dataset group must be available.

Outputs use the run date and table name; the borehole main table uses only the date. A rerun with the same date and format overwrites the corresponding output and upserts its catalog entry. Different dates remain separate snapshots. Generated tables remain local and are ignored by Git. A tracked ingest_manifest.json in each output group retains the measured records across standard catalog regeneration. Catalog records retain source/member identifiers, SHA-256 digests, row counts, byte sizes, source file modification time, ingestion timestamp and comparison evidence. Original inputs remain with their existing owner; a local export does not establish backup or publication. Records are marked local_only: true. Regeneration verifies present outputs against their recorded digest and byte size, and reports availability: missing when an export is absent. Missing exports contribute zero to size_bytes and the available-byte total; measured_size_bytes retains the original run measurement. The manifest itself is metadata and is not scanned as a dataset. Retain or commit the manifests alongside catalog updates when retaining a new run.

Validation and limits

Text fields remain strings: identifiers retain leading zeros, literal NA remains text, and quoted delimiters, escaped quotes and embedded newlines are preserved. Latin-1 is the default encoding, consistent with local BSEE loaders; a UTF-8 byte-order mark selects UTF-8. Other encodings can be selected explicitly. Pickles require memory for their complete DataFrame; text and Parquet outputs are processed in bounded chunks. The current-tier row index is held in memory.

Deduplication removes only exact full-row matches against current-tier files with the same column set, independent of column order. Original field text is compared without trimming, numeric coercion or date normalization. A comparable schema is reported as exact_text_only, because pandas-rewritten numbers such as 0.0 and 0 will not match. A zero exact duplicate count does not establish absence of numeric or key overlap. An equal well identifier alone does not justify deleting different measurements or additional columns. A different schema is recorded as no_comparable_schema; that status does not establish absence of overlap. Duplicate counts include each source occurrence removed. Source counts equal output counts plus removed counts. Existing current-tier files are never overwritten.

Missing inputs, missing current-tier directories, LFS pointers, malformed records, inconsistent widths, duplicate columns, unsafe member names and non-DataFrame pickles and colliding archive table names fail the run. ZIP members are streamed without filesystem extraction. Outputs and catalog are staged until all tables parse successfully; a parse failure leaves existing outputs and catalog intact. Final replacement uses per-file atomic renames; the group of renames is not a filesystem-wide transaction in the event of a disk failure.

File modification time does not establish source vintage or freshness. The recorded WAR exports use older parsed snapshots with unknown vintage, rather than a newly downloaded archive. They do not establish current coverage; a later public archive may contain more rows. No source refresh was performed by this review fix. Exported data remains marked partial for engineering readiness. The positional directdelimit fields need an authoritative schema before physical interpretation. Broader overlap between different schemas and qualification of units are not established by this extraction.

New tests exercise actual script execution, both serialization formats, current-tier overlap, rerun idempotence, all archive members, source precedence, headerless records, malformed-input preservation and the Makefile interface. No test requires a solver.
