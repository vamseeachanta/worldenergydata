ESG carbon inventory module

The worldenergydata.esg_carbon module reads a supplied Climate TRACE source-level CSV, provides facility lookup, and calculates mass totals for observations with the same reporting basis. Missing emissions remain unknown. A complete selected-row total does not establish national coverage.

Source and qualification

The schema basis is Climate TRACE (2026), Climate TRACE Emissions Inventory v5.11.0, September 2026, Data Licensing, Schema, and Citation Guide, section <subsector-name>_emissions_sources.csv metadata, accessed 2026-10-19. The guide defines reported mass in metric tonnes and distinguishes reported zero from blank, null and N-A observations. Its gas metadata distinguishes species from separate CO2-equivalent horizons. No GWP or emission-factor coefficients are included in this module.

The retrieved guide has SHA-256 e0f88eda2e8d127961c7d91fcc1d5eb31bb1fa96e22da56e166fb6c859d33c3e. The URL is mutable; this digest identifies the edition inspected for the implementation. The download page and terms were also opened. The guide states CC BY 4.0 except where otherwise noted; sector-specific restrictions and attribution remain applicable to supplied data. No measured dataset or downloaded source document is distributed here.

The catalog metadata was unavailable in the inspected workspace. No catalog source ID is assigned. The input edition is required and caller-declared; it is not authenticated against an upstream release. The input SHA-256 records the original bytes, including any byte-order mark. Original inputs shall be retained by the caller. Parsing establishes schema compatibility, not freshness, independent accuracy or suitability for regulatory use.

Use

from worldenergydata.esg_carbon import read_climate_trace_csv

inventory = read_climate_trace_csv(
    "inputs/emissions_sources.csv", edition="v5.11.0"
)
observations = inventory.select(source_id="source-identifier", gas="co2")
summary = inventory.summarize(
    iso3_country="USA",
    gas="co2",
    subsector="oil-and-gas-production-and-transport",
)
print(summary.status, summary.total_tonnes)
print(summary.known_subtotal_tonnes, summary.missing_count)
print(summary.edition, summary.sha256)

Filters use exact matches. A summary selection spanning different periods will raise ValueError; matching timezone-aware start_time and end_time filters can select a period. Unfiltered queries do not silently select the latest year or a gas.

Validation and calculation

Required fields are source_id, source_name, iso3_country, sector, subsector, start_time, end_time, gas, emissions_quantity and temporal_granularity. Additional columns are ignored, except an explicit emissions_quantity_units column shall contain tonnes. Required identifiers are nonempty. Country labels require three uppercase letters; membership in an ISO registry is not established. Datetimes without offsets are interpreted as UTC per the guide; explicit offsets are normalized to UTC. End time shall follow start time. Masses shall be finite and nonnegative within this slice. Carbon removals and non-GHG pollutants are outside the supported domain.

Supported labels are co2, ch4, n2o, co2e_100gwp and co2e_20gwp. Duplicate source/gas/period observations, duplicate headers and ragged rows are rejected. A UTF-8 byte-order mark and additional published columns are supported.

For one country, sector, subsector, gas, start time, end time and temporal granularity, the equation is total = sum(reported mass) in metric tonnes, provided every selected mass is available. The dimensional basis is the guide's emissions_quantity definition. No units, gas horizons, periods or sector boundaries are converted. Floating-point overflow is rejected.

Verification and later slices

Synthetic schema fixtures test parsing, provenance, lookup, duplicate rejection and completeness. Independent hand calculations are written in test docstrings: for example, reported masses of 12.5 and 2.5 tonnes sum to 15.0 tonnes; adding an unknown mass cannot establish a total. These fixtures are not measured or published emissions examples.

Live API access, automated downloads, national inventory comparisons, IEA methane ingestion, carbon intensity, CLI integration and regulatory limits remain outside these slices. EDGAR and other comparisons require matching periods, geography, sector boundaries, units and GWP basis before implementation. No compliance verdict is supplied.
