NSTA field metadata enrichment

The fields and wells themes are joined to enrich UK field concepts with operator, depth and oil-field startup year. The synthetic example below returns 120.0 m from matching well depths of 100.0 m and 140.0 m. Screening retains source evidence and missing-data indicators; no field recommendation is qualified.

Source contract

The public NSTA layer schemas were inspected on 2026-10-20. The offshore fields schema provides FIELDNAME, FIELDTYPE, CURR_OPER, STATUS, PROD_DATE, DISC_DATE, DEPTH_M and the CURRLIC/EQUITY slots. The offshore wells top-holes schema provides TARGETFLD for the join and WATDEP_M for water depth in metres. Drilling depth and datum elevation are not substituted for water depth. Only attributes are requested; the coordinate systems are not used for a spatial join.

Startup dates in PROD_DATE are strings. Valid calendar years, year/month strings and ISO calendar dates are parsed. Production startup is retained for all field types; year_first_oil is populated only for the source OIL type. Neither discovery date nor startup date establishes FDP consent or FID.

A finite, nonnegative field depth takes precedence. Otherwise the sample median of finite, nonnegative matching-well depths is used as an estimate. For this even sample, median = (100.0 + 140.0) / 2 = 120.0 m. This definition follows Python's statistics.median documentation (accessed 2026-10-20). The aggregation is an explicit software policy; it is not an NSTA-approved field-depth estimator or an engineering acceptance criterion.

import json
from pathlib import Path
from worldenergydata.ukcs.field_metadata import enrich_ukcs_field_metadata
from worldenergydata.ukcs.field_concept import screen_ukcs_field_metadata

fixture = json.loads(
    Path("tests/unit/ukcs/fixtures/nsta_metadata.json").read_text()
)
meta = enrich_ukcs_field_metadata(
    "EXAMPLE", fields=fixture["fields"], wells=fixture["wells"]
)
screen = screen_ukcs_field_metadata(meta)
concept = screen["field_concept"]
assert concept.region == "uk"
assert concept.water_depth_m == 120.0
assert concept.year_first_oil == 2001
assert meta["metadata_provenance"]["water_depth_m"]["method"] == "median"
assert meta["metadata_coverage"]["fdp_consent_date"] == "NOT_EVALUATED"
assert screen["recommendation_ready"] is False

The example is exercised by test_field_metadata.py; its expected depth is calculated independently in the test docstring. The normalizer copies the input records without mutating them. The same metadata gives the same concepts, scores and evidence, including after the well rows are reordered.

Live access and retained evidence

from worldenergydata.ukcs.metadata_client import NSTAFieldMetadataClient

# field_name is supplied by the caller and identifies a public NSTA field.
meta = NSTAFieldMetadataClient().load_field_metadata(field_name)
# The existing reference chain accepts this dictionary as field_meta.

Each query requests OBJECTID ordering. Offsets advance by received row count, including short pages that still carry the transfer-limit flag. HTTP errors, ArcGIS error envelopes, malformed rows, empty incomplete pages and repeated object IDs fail explicitly. Conflicting field records require reconciliation; record order does not establish precedence. No implicit cache is created.

Per-value evidence includes the source layer URL, source columns, contributing record IDs, transformation and a SHA-256 digest of the contributing attribute snapshot. Dictionary keys and rows are sorted before hashing. This is a digest of canonical attributes, not of the raw HTTP response. Live retrieval adds a UTC timestamp; offline snapshots require their own capture-time record. Consumers retaining datasets shall also retain the original snapshots and retrieval manifest; a digest alone is not a source copy or a freshness assessment.

A supplied HTTP session can archive the original responses when retention is required. The default client returns metadata and digests without saving source bytes; it is an access interface, not a retained dataset.

Coverage and limitations

Status, ownership and full dates remain beside FieldConcept because the shared schema has no corresponding fields. Equity values are preserved without a percentage conversion or a completeness claim. FDP consents remain NOT_EVALUATED until a verified consent source is supplied. A missing depth remains unknown rather than zero; an observed zero is retained.

Well-derived depth represents the contributing sample and can vary across a field. No outlier, datum or spatial representativeness qualification is added. The source schema check is not a live field validation campaign. Reservoir, host, schedule and commercial evidence remain necessary before a field recommendation can be issued. The reference chain's existing pre-tax economics and missing drilling-capital limitations remain outside this metadata change.
