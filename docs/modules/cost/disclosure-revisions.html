Annual disclosure revision contract

Original and revised evidence is retained as distinct immutable records. The current view selects one version per logical disclosure; the history view retains all branches. Annual capex views select current versions before computing differences and carry the selected revision metadata.

Identity and validation

The optional revision block is shared by ingest DisclosureRow and analytics DisclosureRecord. No metadata is inferred for legacy records. Identifiers are caller-supplied, opaque, case-sensitive strings; they are preserved without normalization.

FieldContract
logical_disclosure_keyRequired non-blank identity for one annual metric across versions; one business key and one original per logical key.
version_idRequired non-blank corpus-wide version identity. A different value, citation or metadata under the same ID is a conflict.
revision_classificationoriginal, amended or restated. The classification is supplied by the curator, not inferred from amounts.

The existing ingest business key is (operator, fiscal year, scope type, normalized metric name, project name). Different fiscal years require different logical keys. Analytics records have a single capex metric and use (operator, fiscal year, scope, project name, currency). Currency changes therefore cannot silently create a comparable capex lineage.

Ingest and linkage

ingest_disclosure_rows accepts original records and appends revisions. An exact repeated version is a duplicate; a reused ID with changed evidence is version_id_conflict. Missing parents, cross-key links, competing originals and mixed versioned/unversioned records sharing a business key are revision_lineage_conflict, with a diagnostic in decision.lineage_error. Malformed metadata lands in invalid. Parents must precede children within an ingest batch; an earlier rejected child is not retried automatically.

An imported existing corpus is validated before ingest or selection. Missing parents, cycles and conflicting identities raise ValueError rather than establish current evidence. Unversioned rows retain the previous citation/value duplicate and conflict rules. To migrate an existing logical point, supply a complete explicitly versioned copy of its historical evidence; a versioned row cannot silently replace an unversioned row.

Only backward edges are stored. The superseded-by list is derived by finding rows whose supersedes_version_id equals the requested version ID; forks can produce several children. No original row is edited to add a forward pointer. Exact operator/project matching and scope gating for sanction linkage remain unchanged for every version; value and citation revisions do not change the match key. A business-key correction starts a separate logical record.

Current, history and annual-series rules

load_disclosure_revision_history(records, logical_disclosure_key=...) returns complete, deduplicated version evidence. The full corpus is supplied, even when only one key is requested. Groups sort by logical key; within a group, root-relative depth precedes effective date, publication date and lexical ID. Without a filter, legacy rows retain input order ahead of versioned groups.

load_current_effective_disclosure_rows(records) selects the greatest precedence tuple in each logical group. Unknown dates sort before known dates. A deeper descendant wins over a shallower branch even when the shallower branch has a later date; equal-depth branches use effective date, then publication date, then lexical ID. All losing branches remain in history. Branch tie-breaking is a deterministic display convention, not confirmation of a filing's legal effect. Current refers to the supplied snapshot; no clock-based or historical as-of filter is applied, including for supplied future dates.

Both existing annual views select current rows first, retain selected metadata in revision, and copy provenance. Values remain as supplied; no currency conversion, inflation adjustment or comparability approval is implied. The existing previous-observation difference method is retained; a fiscal-year gap is not interpolated. Legacy rows receive no invented revision label and unrelated legacy series remain available.

Method: retain all three records; follow the parent edge to select 120.0 for 2023; keep 150.0 for 2024. Hand calculation: 150.0 − 120.0 = 30.0 USD million; 30.0 / 120.0 = 0.25, or 25.0 %. History remains [100.0, 120.0, 150.0]; current amounts are [120.0, 150.0]. The selected 2023 row is annotated restated.

Sources and limits

  • Revision plan (2026), Scope Boundaries: identity, backward edges, required publication dates and selection precedence.
  • Ingest plan (2026): legacy citation/value conflict semantics.
  • Analytics plan (2026): current/prior subtraction and ratio definitions; no monetary normalization.

Automated filing discovery, historical restatement backfill, persistence, as-of filtering, and downstream economics integrations remain outside this contract. Source retrieval and intended-use qualification remain independent requirements; a valid revision structure alone does not qualify a monetary value.
