## Findings

1. **MAJOR - Private/quarantine roots can be inspected before quarantine.**
   Evidence: `docs/plans/2026-07-09-issue-910-mnt-ace-ecosystem-data-inventory.md:204-210` lists children and reads manifests before classification; `:212-218` classifies private roots after inspection; `:263` requires representative manifests/files; `:292` admits deep path listing can leak sensitive data.
   Impact: unknown or sensitive `/mnt/ace/*/data` roots can leak child names, manifests, or file evidence into tracked HTML/JSON.
   Concrete fix: classify root source class before any listing/read; default unknown roots to quarantine; allowlist public roots explicitly; for quarantine rows record only root-level metadata and reason. Add tests for unknown/private sibling roots and similar sensitive-name patterns.

2. **MAJOR - Bounded discovery is not enforceable enough to prevent crawling.**
   Evidence: `docs/plans/...inventory.md:198-207` says max depth/file-count limits but gives no numeric bounds; `:245` tests first-level discovery only; `:262` runs against `--root /mnt/ace` with no cap flags; `:253` checks JSON size/path safety but not traversal limits.
   Impact: an implementation could pass the plan while doing recursive `os.walk`, manifest searches, symlink traversal, or unbounded sampling over large/private archives.
   Concrete fix: specify exact caps: discovery depth, per-root sample depth, max entries, max manifest bytes, no symlink following, per-root timeout, and private-root short-circuit. Add tests that fail on depth > allowed, entry count > allowed, symlink cycles, and private-root child reads.

   Concrete fix: either correct `TWO_TIER_DATA.md` in this plan or add a hard AC requiring the report to state the conflict, use the script/test topology as authority, and create/link a follow-on issue for the missing policy/resolver.
