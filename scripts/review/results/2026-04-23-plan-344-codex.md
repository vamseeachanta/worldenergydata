# Plan Review Artifact — Issue #344 — Codex

- Verdict: MAJOR
- Retrieval adequacy: adequate

Key findings
- The versioning contract is still materially deferred: required fields, nullability, meaning of `version_id`, and meaning/cardinality of `supersedes` / `superseded_by` are not fixed.
- The plan does not cleanly separate version semantics from existing duplicate/conflict semantics; the need for a companion logical key is still treated as a risk instead of a defined contract.
- Analytics behavior is underspecified because "latest/current-effective" selection precedence across publication date, effective date, version identity, and lineage edges is not defined.
- The fallback rule for rows without revision metadata is unsafe as written because it can silently collapse unknowns into current rows.
- File/API ownership remains ambiguous (`disclosure_ingest_contract.py` or a new companion module).
- Acceptance criteria are still partly qualitative.

Main blockers to fix
1. Define the concrete identity contract: required fields, allowed nullability/combinations, exact meaning of `version_id` / `supersedes` / `superseded_by`, and explicit distinction between business key, logical disclosure key, and duplicate/conflict classification.
2. Specify executable analytics rules and public boundaries: exact selector precedence for current-effective rows, exact history-access behavior, and the final module/API ownership.
