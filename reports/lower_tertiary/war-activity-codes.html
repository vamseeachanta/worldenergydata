BSEE WELL_ACTIVITY_CD · issue #1065 · WAR vintage 2026-02-19

BSEE publishes no WELL_ACTIVITY_CD domain at all.

Every drilling-day number this repository publishes rests on a twelve-value activity code in BSEE's Well Activity Reports. Not one of those twelve values has a published definition for this field. This page states, code by code, what BSEE actually publishes, what we inferred, and what nobody knows — and links each claim to its source so you can check it rather than trust it.

WELL_ACTIVITY_CD exists only inside the raw dump (mv_war_main_prop). BSEE ships no layout file, no readme and no code table with it, and the field is absent from the eWell WAR field-definitions grid that documents its 23 siblings. It is an undocumented internal column exposed by a raw data release — which is not a criticism of BSEE, but it is a fact every consumer of these numbers needs to know.

This is a BOREHOLE STATUS domain, not an activity domain. Six WELL_ACTIVITY_CD tokens (WO, CHZ, PND, MPF, REC, TBK) do not appear in it at all, and six published borehole codes never appear in WAR.

The six that never appear in WAR are APD, AST, BP, CNL, CT, VCW. The six WAR tokens absent from this list are WO, PND, CHZ, MPF, REC, TBK. Half the observed WAR vocabulary is outside the borehole-status domain entirely: they are related domains, not the same domain, and the published list must not be presented as the WAR list.

4 · The one that moves published economics

PND — everything we have, and no definition

PND is 2.44% of all WAR wellbore-weeks and touches 3,815 wellbores. It is the only undocumented code whose treatment changes numbers we publish, so it gets its own section — and that section still does not tell you what it means, because BSEE has not said.

Observed evidence

PND weeks are the busiest in the file: only 6.1% lack a rig name (vs TA 42.6%, PA 50.1%), the longest median remark of any code (923 chars), the highest BOP rate (53.9%), and the deepest mean DRILLING_MD (16,622 ft, highest of all twelve). DSI/TA/PA own the SUSPEND / NO ACTIVITY language; PND does not. Young code — 0% before 2001, ramping from 2002 (eWell era). Median run of 1 week, sits mid-drilling (mean position 0.39), opens 2,135 wells.

Why it matters to published numbers

Materially moves published economics. If PND is active rig time, excluding it from completion understates. PND = 4,713 days against COM's 5,298 on the published 253-bore population.

How often it actually occurs

2.44% of all WAR rows corpus-wide — NOT the 20-45% previously cited. Only 14% of wellbores use PND at all; among those, median 14.3% of that well's weeks, p90 40%. Rare fleet-wide, concentrated where it appears.

inference Not a definition — do not cite this as one

Best reading: a "pending / status not yet determined" residual dropdown option applied to weeks of real, rig-attended activity. NOT an idle or suspended code. This is inference; BSEE publishes nothing.

This paragraph is the reading of engineers looking at remark text, rig names and depths. BSEE publishes no meaning for PND. Nothing in this box may be used as a definition, mirrored into a code table, or shipped as a label — that is exactly how PND | PENDING/UNKNOWN entered this repository with its uncertainty flag stripped off (#1065).

The row for PND in the table above therefore shows no meaning published, and it will keep showing that until BSEE answers. Source of record: war_activity_codes.yml:105.

5 · What would settle it

One open query to BSEE — and it must cover the whole domain

No amount of further analysis of our own copy of the data can turn an inference into a definition. Only the data steward can.

Outstanding query

  • To — TDM@bsee.gov (BSEE Technical Data Management)
  • Ask — The full WELL_ACTIVITY_CD domain, not PND alone.
  • Codes — WO, CHZ, PND, MPF, REC, TBK (58,229 rows, 16.1% of the corpus)
  • Tracked as — #1065

Do not ask about PND alone. The issue was raised about PND because PND showed up in a rig-day total, but PND is 2.44% of rows and the other five undocumented codes together are 13.66%. A reply that defines only PND leaves the larger hole open and would let this page be quietly retired while most of the vocabulary is still undocumented.

Cheaper avenue, still untried. BSEE's own eWell WAR report viewer renders a STATUS cell per report. If that cell spells the status out rather than printing the token, it is a published answer available today — but it renders through an image pipeline, so it needs one manual browser check on a report known to carry an undocumented code. Until somebody does that, or TDM replies, tier 3 stays empty.
